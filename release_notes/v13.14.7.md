# Changelog

Changes in v13.14.6..HEAD:

## Highlights

- **Aura is the player now** — the full player was rebuilt as an artwork-driven design: the cover leads, the queue lives on a page that turns with it, and the layout has its own portrait, landscape, small-screen, tablet and car shapes instead of one tree squeezed to fit. `PlayerDesignStyle.DEFAULT` is `AURA`, and the selector offers exactly one entry because Aura is the only design the app ships — Expressive (V6) is left in the code but taken out of the selector, and a stored `V6` resolves to Aura rather than keeping a design the settings screen can no longer offer. The layouts are pinned by `PlayerDesignStyleTest`, and every size they are drawn at was captured on the device as a still before the code was settled. *(Hush)*
- **The library searches all seven tabs from one field** — Metrolist renders a search header inside every library sub-screen; Hush's library is one pager host, so the bar sits above the pager instead: a single always-visible field whose query is shared by every sub-screen and survives a tab switch. Matching is case- and diacritics-insensitive (`normalizeForSearch` splits with NFD so `é` matches `e`, then lowercases) and a field-by-field rule (`matchesNormalizedQuery`) that treats a blank query as "everything" and a null value as never matching, pinned by tests. Empty tabs got a shared state with one useful action — search, create a playlist, refresh — instead of a blank page. *(Hush)*
- **Canvas learnt where to get a video, and when not to** — animated artwork used to be one hard-coded supplier. It is now a small provider set behind a source setting (**AUTO, Hush Canvas, Apple Music, Tidal, Spotify**), a health panel that says *per provider* whether it can serve right now (not selected, not connected, disabled, offline, Wi-Fi required, low data mode), and a Wi-Fi-only policy that is enforced twice: where a canvas is resolved, and inside the cache client, so a video download started before the policy changed is aborted rather than finished on a forbidden network. *(Hush)*
- **Four more lyrics sources, each with its own switch** — Zemer, Bini, QQ Music and Genius join the provider list, wired into the same priority order and language rules as the existing ones. Two of them are ports of SpotiFLAC's own Go implementation (QQ Music's base64 LRC payload, Genius's public search plus its `data-lyrics-container` divs, kept in document order), so a track the YouTube-side providers miss now has somewhere else to come from. *(Hush)*
- **The download queue is a home-screen widget** — the active download can be watched from the launcher. It is updated only on discrete events (queue change, status change, coarse progress steps) and never per progress byte, and the last state is persisted so a launcher-driven refresh (reboot, resize) renders without the service running. *(Hush)*
- **Playlist covers repair themselves** — YouTube Music serves playlist artwork from URLs that lapse, and a stale URL stored in the playlist row keeps failing with 4xx while the cover on YouTube's side is perfectly fine. A load of such a URL now asks the cover repository for the playlist's current artwork, persists it over the expired row and retries, and the rule is pinned by `PlaylistCoverInterceptorTest`. The tag chip row also got the ordering it was missing: **Arrange playlist tags** is a drag-to-reorder dialog whose order is saved as one preference, with tags the user has not arranged appended at the end so a newly created tag still appears. *(Hush)*
- **A launch no longer waits for the database** — `InternalDatabase.newInstance` used to force `openHelper.writableDatabase` before returning, so the open, the schema check and the corruption repair ran on whichever thread asked Hilt for the singleton: `MainActivity`'s injection in `onCreate`, before the first frame. Measured on the NE2211: **39-41 ms** warm, and the whole **175 ms** open on a fresh install, because injection follows `App.onCreate` by only milliseconds. The database is now built without being opened, Room opens the file on first use (on its own executors), and the repair moved into that open path in `RepairingOpenHelperFactory`, where it still runs before any query. *(Hush)*
- **Every release now ships a baseline profile** — a profile generated from a first-run journey (cold start → home feed scroll → mini player open/back → warm start) is committed at `app/src/main/baseline-prof.txt` — **51,996 rules** — and every variant merges it. R8 rewrites them against the release mapping (57,456 merged rules become 32,795 obfuscated ones) and packages `assets/dexopt/baseline.prof` (**25,942 B**, plus a 4,041 B `.profm`) in the release APK. Measured on the NE2211 in a two-cycle interleaved A/B of byte-identical APKs: first cold start after install **470.5 → 305.5 ms** and repeat cold starts **359.5 → 234.8 ms**, **−35%** either way. The condition is the one that matters: installed normally the package sits at `Dexopt state: [status=verify] [reason=install]` and the gain only appears once something compiles the app *with* the profile — which is what the profile-driven benchmark measures, not what a normal install gets for free. *(Hush)*

## Player

- **The codec row stopped repeating itself** — the provenance phrase under a served row says where its facts came from, and one of the four origins was already in the line: a row backed by a download or by SpotiFLAC's cached playback file read `FLAC • 1411 kbps • … (device cache) • codec from a file on this device` — one fact twice, in the longest of the four phrases, on the line on the screen with the least room to spare. That source is now named by nothing; the other three are unchanged (`this session's resolve`, `an earlier resolve`, `the decoder`), because each names something the row cannot say for itself. The phrase for a source is a resource id rather than a sentence inside Compose, so which sources are named is a decision `FormatRowSourceLabelTest` reads: it exists for every source except a device file, and no two sources share one. *(Hush)*
- **A file-backed codec row now says what the file is, or says nothing** — a SpotiFLAC-cached track read `MEDIA • 0 kbps • 2 MB • …`, and both halves were unit mistakes. The playback cache writes every file as `<key>.media` — all 20 entries in the device's cache index carry `extension: "media"` — and the row built its container out of that *file extension* (`audio/media` → `MEDIA`), while its rate was `sampleRate * bitDepth * 2` divided by 1000 on its way into a field every reader divides by 1000, so `705` rendered as `0 kbps`. The entry's own figures turn out not to describe the file either: an HE-AAC entry said `22050` where Media3 (`bitrate=48017`) and ffprobe both decode `44100`, and three FLAC entries claim `29539`, which is not a sample rate at all. `SpotiFLACFileFormat` now builds the row out of the three facts the device can prove — the container (taken from the *codec*, so `FLAC`, `MP4`, `OGG`, `MPEG`), the codec and the file's size — and states no rate at all, and `DecodedAudioRow.withDecodedRate` fills the rate from the only thing that measured these bytes, Media3's selected audio track; it is applied to every device-file row, fresh, stored or scanned. A rate that cannot be rendered is no longer printed either: `formattedBitrate` treats anything under 1 kbps as the unit mistake it is and reads `Unknown`, which the row omits, and the resolution path's `1411` fallback — 1411 kbps written into a bps field — is now `1_411_000`. Read on the NE2211 through the player's own codec line: `MP4 • 48 kbps • 4 MB • SpotiFLAC · ytmusic (device cache)`. The lossy case is the one exercised on the device; the FLAC path goes through the same builder and is pinned by tests. `SpotiFLACFileFormatTest` and `FormatEntityRateTest` hold both rules. *(Hush)*
- **The track-change diagnostics are a debug build's alone** — the panel that draws a track change over the artwork was already gated on `BuildConfig.DEBUG`, but the `ARRIVAL` line it feeds was not: Hush plants `GlobalLogTree` in every build, so a shipped build formatted a line per arrival — a queue of them per skip — into the log buffer it keeps for the field, for a reader who cannot see the panel it belongs to. That line is debug-only now, which is checkable rather than asserted: the release APK's dex contains no `ARRIVAL` tag, no log format and none of the panel's own literals (R8 folds the `BuildConfig.DEBUG` branch away), while the debug build keeps all of it and still draws the panel over the artwork. *(Hush)*
- **A turn becomes a settle** — portrait and landscape are two different layouts, not one layout re-measured: six player trees differ behind that choice, and because they are handled by `configChanges` the activity is not recreated and nothing is on screen between the two — the old tree is gone and the new one is already at its final size on the next frame, which is why a turn read as a cut. The arriving layout now starts at **0.94** scale, **0.55** alpha and rides up from below, so the cut reads as a settle. *(Hush)*
- **The player sheet no longer recomposes itself while it moves** — `BottomSheet` read `BottomSheetState.value` and `.progress` *during composition* for its own offset, its corner radius and the alpha of its surface, and `BottomSheetPlayer` read the same value to decide what colour that surface should be. Every pointer sample of a drag and every frame of an animation therefore recomposed the sheet **and the screen inside it** — a full player with a backdrop image and a blur. All of those reads now happen where they are used: the offset, the corner radius and the clip are `graphicsLayer` properties, and the surface is a `drawRect` in `drawBehind` whose alpha comes from a new `backgroundAlpha` lambda. A drag costs a layer update instead of a recomposition. *(Hush)*
- **One of those reads was doing nothing at all** — the `backgroundColor` `BottomSheetPlayer` computed from `state.value` was never consumed by anything: a full recomposition of the player, on every frame of every drag, for a value that was thrown away. *(Hush)*
- **The sheet no longer subcomposes** — its content was wrapped in a `BoxWithConstraints` although that content is a `BoxScope` lambda and cannot read constraints at all, so every mount measured the whole player a second time for nothing. It is a `Box` now. *(Hush)*
- **Opening the player went from a second to a quarter of a second** — the programmatic open/close (a tap on the mini player, the back gesture, `expandSoft`) ran on `Spring.StiffnessLow`, which takes **1059ms** to cross a phone screen, on an interaction a person triggered by tapping. `StiffnessMedium` covers the same travel in **277ms** and lands on exactly the same bound — both numbers are asserted by `PlayerSheetMotionTest`. Both sheet springs also carry `visibilityThreshold = 0.5.dp`: a `Dp` spring's default is a *hundredth of a pixel*, so the tail of every transition was frames of a full-screen sheet being re-drawn for movement no display can show. *(Hush)*
- **The mini player's swipe stopped recomposing the mini player** — `SwipeableMiniPlayerBox` handed its content the drag offset as a `Float`, so the animated offset was read during composition and the pill, its gradient, its artwork and its visualiser re-ran on every frame of a swipe. The offset is handed over as a provider (`() -> Float`) now and read inside the caller's `graphicsLayer`, and the skip affordance's visibility and direction are `derivedStateOf`s that flip at their thresholds rather than being recomputed per frame. *(Hush)*
- **The navigation bar rides the sheet in a layer** — the bar that slides away as the player opens used a placement `Modifier.offset { }`, which put a layout pass on every frame of a drag. *(Hush)*

## Library

- **Search is a property of the library, not of a tab** — one bar above the pager (`LibrarySearchBar`), one query string, every sub-screen reading it: songs, albums, artists, playlists, Spotify playlists, mixes and podcasts. Because the query outlives the tab, a search started in Playlists is still filtering when the user lands on Albums, which is the point of the single host. *(Hush)*
- **Matching is normalised once and shared** — `String.normalizeForSearch()` (NFD split, combining marks removed, lowercased, trimmed) and `matchesNormalizedQuery()`, so `Beyonce` finds `Beyoncé` and the query is normalised by the helper itself rather than by every caller. The contract — blank matches everything, null values never match — is what the callers rely on, so it is pinned rather than assumed. *(Hush)*
- **Empty tabs suggest something instead of saying nothing** — `LibraryEmptyState` draws the same round icon, headline and single action button in every library screen, and the action is the useful one for that screen: search, create a playlist, or refresh. *(Hush)*
- **Tags can be arranged, and the arrangement survives a new tag** — the chip row's order is a saved comma-separated preference applied by the library's tag filter; a drag-to-reorder dialog writes it, and any tag the user has not arranged yet is appended rather than dropped, so a newly created tag still appears where it can be found. Both halves are pure functions and tested. *(Hush)*

## Lyrics

- **Zemer, Bini, QQ Music and Genius** — four providers behind the existing interface, each with its own enable switch and its own preference key, and all four participating in the same priority order and language filter as the providers that were already there. *(Hush)*
- **Two of them are ports, not new clients** — QQ Music's public search plus its lyric endpoint (a base64 LRC payload) and Genius's public multi-search plus its `data-lyrics-container` divs, each taken from SpotiFLAC's Go backend (`lyrics_qqmusic.go`, `lyrics_genius.go` and the Genius half of `lyrics_paxsenix.go`) so the phone and the engine agree about what a source returns. Genius renders each verse as its own container, so document order is preserved deliberately. *(Hush)*
- **Provider order is editable where the switch is** — the priority list is a drag-reorderable component in lyrics settings, and the settings screen is the one place that reads the enable keys, so a provider that is off can no longer be ordered as if it were on. *(Hush)*

## Artwork and Canvas

- **A `:canvas` module of its own** — the canvas sources are a source set with their own manifest and cache, so the app depends on a provider chain instead of owning four implementations inside the player. *(Hush)*
- **Spotify canvas, from ArchiveTune** — a track is found through the pathfinder `searchDesktop` query (reusing `Spotify`, which owns token and hash handling), and its clips come from the `canvaz-cache` protobuf endpoint, which additionally requires a client-token handshake; the access token and client id that handshake needs arrive in the same response, so a session is fetched fresh (three small requests, kept in memory until 30 s before it expires) rather than persisted half of it. The provider never throws for ordinary failures — it runs inside the AUTO chain, where a failure has to degrade to "no canvas from this source". *(Hush)*
- **Apple Music and Tidal join it** — an Apple Music provider that searches the catalogue and its editorial videos with a web token fetched on demand, and a Tidal provider behind the same interface, so AUTO can try Apple Music first and still fall back. *(Hush)*
- **The settings panel answers "can this source serve me right now"** — one row per provider with its own state (`NOT_CHECKED`, `CHECKING`, `AVAILABLE`, `UNAVAILABLE`, `NOT_SELECTED`, `NOT_CONNECTED`, `DISABLED`, `OFFLINE`, `WIFI_REQUIRED`, `LOW_DATA_MODE`), because "no canvas" has six different causes and a blank artwork area names none of them. Availability rules and the wire codec are both tested. *(Hush)*
- **Wi-Fi only is enforced where the download happens too** — resolving a canvas is gated where it happens, but a video download keeps running after the resolve finishes, so the cache client consults the same policy and aborts a download the network no longer allows. Defaults are chosen so behaviour before any observer has run is the behaviour that shipped. *(Hush)*

## Downloads and the widget

- **The widget is event-driven on purpose** — updates arrive on queue change, status change and coarse progress steps, never per progress byte, and the last pushed state is persisted so a launcher-driven refresh (reboot, resize) renders correctly with the service not running. *(Hush)*
- **ReplayGain can be written into downloads** — an opt-in switch that embeds loudness metadata so players honouring ReplayGain keep volume steady across tracks. *(Hush)*
- **Refetch song** — the player's menu can ignore the cache and play a track from the source again, which is the one action for "this copy is wrong", and it says when a track is a download that will play from the file regardless. *(Hush)*

## Android Auto

- **The lossless offer reaches the car, which is where the banner cannot** — the offer to turn SpotiFLAC on is a banner on a screen a driver is not looking at, so the same offer is now one line at the top of the car's root library: `enable_lossless`, playable and not browsable (the only thing a car can do with a list entry is play it, and there is nothing behind this one to open), titled *Lossless audio is available* and subtitled *Tap to turn on and play*. `AndroidAutoPlaylists.offersLossless` publishes it from four conditions, each one a way the entry would otherwise lie: the lossless runtime has to be in this build, SpotiFLAC has to be off, the phone's banner must not have been dismissed, and low data mode must be off — the state in which the Audio Sources screen refuses to turn SpotiFLAC on at all, because every SpotiFLAC play is a whole lossless file over a metered link. The launch counter is deliberately not consulted: it rations a banner that interrupts a launch the user did not ask for, and this is one line in a list they opened themselves. Tapping it writes the one preference the Audio Sources switch writes and nothing else — it does not mark the offer answered, so a driver who turns lossless off again is offered it once more — and it answers the play request with **nothing** rather than with items, because every item list `onSetMediaItems` returns is applied and applying one re-opens the current stream: returning the queue exactly as it stands, and returning it with `C.TIME_UNSET` instead of a position, were both measured to restart the track a driver was on. Answering with nothing is what a car's own legacy transport path does nothing with — no result, no error, no change — so the tap is silent and the music never stops. Measured across the tap while a track was playing: position **6068 → 12109 → 18119 ms**, unbroken, with the preference flipped. With nothing loaded the tap loads the queue the driver would have resumed, so the car's play command has something to play; and the car's *add to queue* on the entry is the same wish and flips the same preference, but the item is never queued — a question is not a song. *(Hush)*
- **The offer is checkable from a shell, with no head unit in the room** — `AutoLibraryDebugReceiver` gained a `spotiflac` switch name (the DataStore key the Audio Sources screen writes) and its browse report prints one `lossless offer: offered=… (runtime=… spotiflac=… dismissed=… lowData=…)` line, because the entry is published from four states at once and a tree showing it present or missing without them is a result with no cause. Its `play` op drives the tap, and its report line now names the player's state as a word and carries a position — `state=3` and `state=2` cannot be told apart at a glance, and the difference between *loaded* and *audible* is the whole question for this entry. *(Hush)*

## SpotiFLAC

- **The app says at launch when lossless is parked** — the engine's state was already computed for Audio Sources and for the resolve path, and both are places the user has to go looking. The one moment the app knows the answer without being asked is startup, right after the renewer has had its turn, so a launch notice says it there: without one, a user who enabled SpotiFLAC and never opened Audio Sources hears YouTube for every track with no statement anywhere that lossless is parked, which reads as the engine being broken rather than as a session needing one check. Dismissal lasts for the process, so it comes back next launch while the state is unchanged. *(Hush)*
- **"Try again" is one action, in one implementation** — renewing and checking are two jobs, but "try again" is one thing to ask for, and doing them in that order is the answer: the gateway rotates every session it still accepts, and whatever it turns down cannot be renewed at all (a record bound to an extension version that has since moved answers a bare `403` from `/v2/session/refresh`, and a source with no record has nothing to refresh), so those are handed to the verifier, which is the only thing that can mint a replacement. `SpotiFLACSessionRecovery` owns that sequence and both surfaces — the launch notice's Renew and Audio Sources' Renew — call it, because two copies of "what Renew does" is exactly how the two came to disagree. *(Hush)*
- **A verification says so, in the middle of the app** — a verification is the only thing in the lossless side that costs the user something (a Cloudflare check) and also the moment the engine goes from "nothing can be fetched" to "this source can". That landing used to be reported only where a screen happened to look; it is now a one-line banner reported from `SpotiFLAutoVerifier.finish`, which is the single place a source becomes usable whatever verified it — the automatic overlay, the browser route, Audio Sources' own challenge, or the grant deep link — so no surface can verify a source without saying so. One message at a time, and it clears itself, because a run works through several sources in sequence. *(Hush)*
- **The offer to turn lossless on is made once at launch, and is an offer** — SpotiFLAC is the one thing that changes what a track *is*, and it is off until someone finds Audio Sources and flips a switch they had no reason to look for, so a launch-time card names it, says who it needs and takes the user to the switch. It is decided from the *stored* preferences, once, at launch — never from a preference's default, which is the whole correctness of it: every preference read through `rememberPreference` starts at its default for a frame or two, so a banner that asked then would offer a feature the user already turned on. Appearances are counted and capped so it asks rather than nags, and the close button is the user's final no for that install. *(Hush)*
- **The four session surfaces are tested as decisions** — `SpotiFLACSessionNoticeTest`, `SpotiFLACSessionRecoveryTest`, `SpotiFLACVerifiedBannerTest` and `SpotiFLACLosslessNudgeTest` read what each one will say and when, because all four are wording and conditions rather than drawings. *(Hush)*

## Playback and storage

- **A queue that is already on this device costs no provider request** — the lookahead is the one path that fetches *ahead* of the user, so a wrong answer is not a slow start but a provider sweep, per source, for bytes that were about to be read off disk. Measured on the reporting device, every warm of a track that had already been streamed was a full six-source sweep, because the guard asked only about files the app owns and a streamed track keeps its bytes in Media3's cache instead. 'Local' is now the union of every way a track can be local — user download, SpotiFLAC playback file, streaming cache — written as a union deliberately, because "not local" has to mean *nothing* is local, and a rule that must be extended whenever another store appears is a rule that is eventually extended in only the place it was noticed. The direction that has to stay fetchable is pinned too. *(Hush)*
- **The database's open failures are classified** — a file that does not match this build's schema is repaired as before, and the repair decision is now a named predicate (`shouldResetDatabase`) rather than a string test inside the loader, so "Room cannot verify the data integrity" and "something is wrong with the device" are told apart where they are decided. *(Hush)*

## Settings

- **Hide YouTube Shorts** — leaves Shorts shelves out of Home, Search and Explore. *(Hush)*
- **Add songs to playlist at Beginning or End** — the one preference every add-to-playlist path reads, instead of each path having an opinion. *(Hush)*
- **Reset listening stats** — starts listening time and play counts over, behind a confirmation because it cannot be undone. *(Hush)*
- **Sponsor Block is one group** — use, auto skip and show-unit-skip-button together, so the two halves of the feature are no longer in different places. *(Hush)*

## Release engineering

- **A benchmark module, so the numbers are re-runnable** — `:benchmark` plus `app/src/benchmark` generate the baseline profile and measure startup against a budget (`StartupBudget`), and the plugin's own collection output (`app/src/*/generated/`) is ignored while the rules it produces are committed at `app/src/main/baseline-prof.txt`. `docs/baseline-profile.md` records what the profile buys and, in the same document, the condition under which it buys nothing. *(Hush)*
- **The SpotiFLAC Go AAR halved** — `app/libs/gobackend.aar` went from **33,333,337 to 18,472,589 bytes**, with `scripts/build-spotiflac-aar.sh` and its new pin handling rebuilt around what is actually needed at runtime, and `scripts/spotiflac-backend-pins.sh` holding the backend pins. `docs/spotiflac-go-aar-size-investigation.md` is the measurement behind it. *(Hush)*
- **The Rust migration is documented before it is attempted** — `docs/spotiflac-rust-migration-plan.md`, `-driver-analysis.md` and `-phase3-mapping.md` map the Go surface onto a Rust replacement, with `scripts/build-spotiflac-rust.sh` materialising a pinned worktree. None of it ships in this release; it is the plan the next one works from. *(Hush)*
- **The Aura and strip probes are scripts, not screenshots in git** — `scripts/aura-strip-align.py`, `aura-strip-probe.sh` and `aura-strip-size-sweep.py` measure the landscape provenance pill against the action row it is supposed to span, which is a runtime width nothing else checks. *(Hush)*
