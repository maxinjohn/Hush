# Changelog

Changes since v13.12.0:

## Highlights

- **First-song startup fixed** — `restorePersistentQueue()` now kicks off the playback URL prefetch *before* `player.prepare()`, so the ExoPlayer loader awaits the in-flight resolution instead of forcing a cold synchronous resolve after relaunch. *(Hush)*
- **Faster BotGuard pre-warm** — pre-warm now runs concurrently with the network auth refresh and is seeded from stored prefs, so it's no longer blocked on a network round-trip. App, service, and session-collector pre-warm call sites were deduplicated. Post-refresh pre-warm re-triggers if sessionId changed. *(Hush)*
- **Waze play/pause fixed** — removed a duplicated dead-code branch in `handleWazeCommand()` that swallowed commands, and fixed shim state drift so the framework's state-dependent play/pause toggle always targets Hush's real player state. Hush now force-publishes its state after every play/pause command. *(Hush)*
- **Search never gets stuck** — if the summary or filter search fails to load, the results screen now shows an error with a retry button instead of an infinite loading shimmer. Local search queries are bounded at the SQL level to prevent memory spikes on large libraries. *(Hush)*
- **Memory everywhere** — Coil image memory cache scales with the device (`maxSizePercent(0.20)`), image cache is cleared on `TRIM_MEMORY_UI_HIDDEN`, the low-RAM 128MB player-cache clamp was removed so the user's cache size is always respected, and the player backdrop decodes at 1536px instead of 2048px. *(Hush)*

## Playback

- **Prefetch before prepare on restore** — `restorePersistentQueue()` starts the URL prefetch for the current track before `player.setMediaItems()`/`player.prepare()`, letting `resolvePlaybackDataSpec()` await an in-flight prefetch (up to 30s) instead of resolving cold and synchronously. *(Hush)*
- **Concurrent pre-warm** — `App.kt` pre-warms the BotGuard engine from the stored session immediately at startup, concurrently with `refreshPlaybackLoginContext()`. The post-refresh duplicate pre-warm was removed. *(Hush)*
- **Service pre-warm from prefs** — `MusicService` seeds its pre-warm from stored playback auth prefs instead of triggering a network refresh when the in-memory session is empty. *(Hush)*
- **Post-refresh pre-warm re-trigger** — if `refreshPlaybackLoginContext()` changes the sessionId, BotGuard is pre-warmed again with the new session to avoid a 15 s cold WebView bootstrap on first playback. *(Hush)*
- **Redundant prefetch removed** — second `startPlaybackUrlPrefetch()` call after restore was removed (the first one started inside `restorePersistentQueue()` already covers it). *(Hush)*
- **Single prefs fetch on restore** — all restore-related DataStore prefs read in one blocking call instead of multiple sequential 1.5 s timeouts. *(Hush)*

## Waze Bridge

- **Per-command throttle** — shim now throttles only identical commands (300 ms) instead of a single global throttle that dropped rapid play→pause toggles. *(Hush)*
- **Seek suppression fix** — `shouldIgnorePendingSnapshot()` now suppresses only the *position* field during an active seek; state/metadata changes are always applied so the play/pause toggle never drifts. *(Hush)*
- **Publish after seek/skip** — Hush now publishes a force snapshot after `seek` and `skip_to_queue_item` commands so Waze updates immediately. *(Hush)*
- **Queue data in snapshots** — full queue (items, revision, title) is now sent in `WAZE_METADATA_UPDATE` broadcasts; Waze queue/up-next UI and queue-item selection now work. *(Hush)*
- **Cold-start command queue** — multiple deferred Waze commands during cold start are now queued and all executed (previously only the last one ran). *(Hush)*
- **Snapshot handshake on connect** — shim sends a `"sync"` command to Hush on every bind/init/reconnect; Hush replies with a force snapshot so Waze shows the real state immediately even when paused. *(Hush)*
- **Unified command path** — the dynamic broadcast receiver path now routes through `handleWazeCommand` so it gets the same debounce, cold-start gating, and queue-restore logic as the service-intent path. *(Hush)*
- **Command handling fix** — removed the duplicated empty `else if (queueRestoreCompleted.value)` in `handleWazeCommand()` that dropped play/pause commands when the queue was empty after a completed restore. *(Hush)*
- **Shim state drift fix** — `shouldIgnorePendingSnapshot()` no longer discards snapshots that conflict with the optimistic state; conflicting snapshots are applied so the shim always reflects Hush's real state. Only the echo of the shim's own optimistic update is suppressed. *(Hush)*
- **Post-command resync** — `WazeCommandReceiver` force-publishes a fresh snapshot after every play/pause/stop command so the shim converges to the real state within one round-trip. *(Hush)*
- **Shim version** — Waze bridge shims bumped to 13.13.0 (versionCode 162), matching the Hush release so installed shims upgrade correctly. *(Hush)*

## Search

- **No more stuck loading** — `OnlineSearchViewModel` tracks summary and per-filter load failures; `OnlineSearchResult` shows an error + retry button instead of an infinite shimmer when loading fails. *(Hush)*
- **Retry support** — `OnlineSearchViewModel.retry()` clears failure flags and reloads the current search. *(Hush)*
- **Bounded local search** — `LocalSearchViewModel` passes `MAX_RESULTS_PER_FILTER` (100) as the SQL `LIMIT` for song/album/artist/playlist queries instead of loading every match into memory. *(Hush)*
- **Memoized derivation** — online search results no longer re-run `distinctBy`/`sortedItems` on every recomposition. *(Hush)*
- **Bounded discovery queries** — `DynamicSearchPlaceholder` uses `LIMIT 50` variants of the liked-songs and top-artists queries instead of full-table scans. *(Hush)*

## Memory

- **Coil memory cache scales** — `maxSizeBytes(16/32MB)` replaced with `MemoryCache.Builder().maxSizePercent(this, 0.20)` so it scales with device heap (low and high RAM). *(Hush)*
- **UI-hidden cache clear** — `TRIM_MEMORY_UI_HIDDEN` now clears the image loader memory cache when the UI is fully hidden. *(Hush)*
- **No low-RAM player cache clamp** — the 128MB default override for low-RAM devices was removed; the user-configured cache size is always honored. *(Hush)*
- **Smaller backdrop decode** — V7 player backdrop max decode reduced from 2048px to 1536px (~44% less memory per backdrop bitmap). *(Hush)*

## Build

- Version bumped to 13.13.0 (versionCode 161). Waze bridge shims bumped to 13.13.0 (versionCode 162). *(Hush)*
